(Level AAA)

## 요약

<dl>
<dt>목표</dt>
<dd>사용자가 재인증으로 인해 정보나 맥락을 잃지 않는다.</dd>
<dt>할 일</dt>
<dd>재인증 과정에서 사용자의 이전 활동과 데이터를 보존한다.</dd>
<dt>중요성</dt>
<dd>일부 사용자는 활동을 완료하는 데 추가 시간이 필요할 수 있다.</dd>
</dl>

<Card title="성공 기준(SC)">
인증된 세션이 만료되면, 사용자는 재인증 후 데이터 손실 없이 활동을 계속할 수 있다.
</Card>

### 의도

이 성공 기준의 목적은 모든 사용자가 인증이 필요한 작업을 완료할 수 있도록 하는 것이다.
이러한 작업에는 비활성 시간 제한이 있거나, 작업을 완료하는 도중에 사용자를 로그아웃시키는 다른 상황이 있을 수 있다.

보안상의 이유로 많은 사이트가 일정 기간 활동이 없으면 인증 시간 제한을 적용한다.
이러한 시간 제한은 장애가 있는 사람에게 문제를 일으킬 수 있는데, 이들이 활동을 완료하는 데 더 오래 걸릴 수 있기 때문이다.

또 다른 사이트는 사용자가 다른 컴퓨터에서 웹사이트에 로그인하거나, 지금 사용하는 사람이 처음 로그인한 본인이 맞는지 의심스럽게 만드는 다른 활동이 발생하면 세션에서 로그아웃시킨다.
사용자가 작업 도중에 로그아웃되었을 때는, 이미 입력한 데이터를 잃지 않고 재인증하여 작업을 계속할 수 있게 하는 것이 중요하다.

<Card title="참고">
세션 시간 제한과 재인증 요청을 적용하는 사이트도 [2.2.1 시간 제한 조정](../timing-adjustable) 같은 다른 기준의 요구 사항을 따라야 한다.
</Card>

### 이점

*   이 성공 기준은 활동을 완료하는 데 시간이 더 필요한 사람에게 도움이 된다.
인지적 제약이 있는 사람은 읽기가 느려서 설문지를 읽고 응답하는 데 시간이 더 걸릴 수 있다.
스크린 리더로 상호작용하는 사용자는 복잡한 양식을 탐색하고 완료하는 데 시간이 더 필요할 수 있다.
운동 장애가 있거나 대체 입력 장치로 탐색하는 사람은 양식을 탐색하거나 양식 안에서 입력을 완료하는 데 오랜 시간이 걸릴 수 있다.


### 예제

<dl>
    <dt>쇼핑 사이트의 결제</dt>
    <dd>
        사용자가 쇼핑 사이트에 로그인해 있다.
        결제 과정 도중에 사용자가 방해를 받아 컴퓨터를 떠나야 한다.
        자리를 비운 사이, 사이트가 곧 시간이 초과된다고 알리며 시간 제한을 연장할 수 있는 기능을 제공하지만, 사용자가 자리에 없어 시간 제한이 연장되지 않고 사용자는 로그아웃된다.
        사용자가 컴퓨터로 돌아오면 재인증을 해야 한다. 로그인한 후, 결제 과정이 동일한 정보와 동일한 단계로 복원된다.
        세션이 시간 초과되었더라도 서버가 제출된 내용을 일시적으로 받아 저장해 두었고 재인증이 완료된 후 사용자를 같은 상태로 복원했기 때문에, 사용자는 어떤 데이터도 잃지 않았다.
    </dd>
    <dt>이메일 프로그램의 인증</dt>
    <dd>
        이메일 프로그램에는 30분 인증 시간 제한이 있다.
        프로그램은 시간 초과가 발생하기 몇 분 전에 사용자에게 메시지를 표시하고 재인증을 위해 새 창을 열 수 있는 링크를 제공한다.
        진행 중인 이메일이 포함된 원래 창은 그대로 유지되며, 재인증 후 사용자는 해당 데이터를 보낼 수 있다.
    </dd>
</dl>

### 기법

이 섹션의 각 번호가 매겨진 항목은 접근성 지침 실무 그룹이 이 성공 기준을 충족하기에 충분하다고 판단하는 기법 또는 기법의 조합을 나타낸다. 기법은 기준의 최소 요구 사항을 넘어설 수 있다. 이러한 기법에서 포괄하지 않은 기준 충족의 다른 방법이 있을 수 있다. 다른 기법 사용에 대한 정보는 [WCAG 성공 기준에 대한 기법 이해](../understanding-techniques), 특히 "기타 기법" 섹션을 참조하라.

#### 충분 기법

*   다음 기술 중 하나를 사용하여 데이터 손실 없이 계속할 수 있는 옵션 제공:
    *   [G105: Saving data so that it can be used after a user re-authenticates](https://www.w3.org/WAI/WCAG22/Techniques/general/G105)
    *   [G181: Encoding user data as hidden or encrypted data in a re-authorization page](https://www.w3.org/WAI/WCAG22/Techniques/general/G181)

참고

시간 제한에 대한 알림 제공과 관련된 기술은 [성공 기준 2.2.1을 해결하기 위한 기술](timing-adjustable#techniques)을 참조하라.
